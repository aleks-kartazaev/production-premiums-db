# Описание фич проекта

Схема базы данных (`schema.sql`, `schema.dbml`, `ERD_sql.png`) — общая для всех трёх фич. Ниже — описание функциональности, которая на ней работает.

## Фича 1: Учёт выработки сотрудников

**Цель:** Автоматизировать сбор и расчёт данных о количестве выполненных изделий и затраченных часах для каждого монтажника.

**Что делает:**
1. Хранит информацию о сотрудниках, изделиях и нормах времени.
2. Автоматически рассчитывает коэффициент выработки (соотношение «норма / факт») по каждому изделию за месяц.
3. Формирует сводную таблицу с показателями выработки по изделиям.

**Результат:** Время на учёт выработки сократилось с 3–4 часов до 15 минут в неделю, количество ошибок при расчёте снизилось на 90%.

**Задействованные таблицы:** `employees`, `items`, `norms`, `productivity`.

**Диаграммы:** `diagrams/feature-1/` (BPMN AS-IS/TO-BE, Sequence, C4 context/container).

## Фича 2: Расчёт и начисление премий

**Цель:** Автоматически рассчитывать размер премии на основе выработки сотрудника и справочника коэффициентов.

**Что делает:**
1. Хранит справочник коэффициентов премии (диапазон соотношения «норма / факт» → процент от оклада).
2. Агрегирует коэффициент выработки по сотруднику за месяц (среднее по всем изделиям).
3. Автоматически определяет коэффициент премии для каждого сотрудника по справочнику.
4. Рассчитывает предварительную сумму премии и формирует таблицу для утверждения.

**Результат:** Время на расчёт премий сократилось с 4–5 часов до 30 минут в месяц, конфликты из-за несправедливых премий снизились.

**Задействованные таблицы:** `bonus_coefficients`, `bonus_accruals` (+ данные из фичи 1).

**Диаграммы:** `diagrams/feature-2/` (BPMN AS-IS/TO-BE, Sequence, C4 context/container).

## Фича 3: Утверждение премий

**Цель:** Дать начальнику участка инструмент для финального утверждения расчёта премий.

**Что делает:**
1. Отображает финальную таблицу с расчётом премий.
2. Позволяет утвердить расчёт или скорректировать сумму с обязательным комментарием.
3. Фиксирует дату, время и автора утверждения, блокирует повторное утверждение без отмены.

**Результат:** 100% расчётов проходят через шаг утверждения, выплаты происходят вовремя за счёт напоминаний.

**Задействованные таблицы:** `bonus_accruals` (статусы, `approved_by`), `periods`, `audit_log`.

**Диаграммы:** `diagrams/feature-3/` (BPMN AS-IS/TO-BE, Sequence, C4 context/container).
